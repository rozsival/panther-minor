# 🧰 CLI Reference

> `./bin/panther-minor` is the single entrypoint for host setup, model management, certificates and the Compose
> cluster. It is generated by [Bashly](https://bashly.dev/) from authored sources in `cli/`; this page is both the
> user reference and the maintainer contract for changing it.

**Related:** [Installation](installation.md) · [Operations](operations.md) · [Models](models.md) ·
[Development](development.md)

---

## 📍 At a glance

| Audience           | Use this                                                       |
| ------------------ | -------------------------------------------------------------- |
| CLI users          | Run `./bin/panther-minor` from the project root                |
| CLI maintainers    | Edit authored sources in `./cli/*`                             |
| Generated artifact | `./bin/panther-minor` is build output, not the source of truth |

> [!IMPORTANT]
> Do **not** edit `./bin/panther-minor` directly. Update the authored Bashly sources and regenerate it instead.

## 🗂️ Command groups

| Command       | Purpose                                                 |
| ------------- | ------------------------------------------------------- |
| `setup`       | Prepare and secure the host machine                     |
| `models`      | Manage model downloads, cache, and throughput baselines |
| `proxy`       | Work with certificate and proxy-related tasks           |
| `cluster`     | Build, start, and stop the AI stack                     |
| `logs`        | Inspect service logs                                    |
| `update`      | Refresh project assets or dependencies                  |
| `completions` | Print shell completion scripts                          |

```bash
./bin/panther-minor --help
./bin/panther-minor <command> --help
```

### Shell completions

```bash
source .bashrc                                   # bash, from the repository root
eval "$(./bin/panther-minor completions zsh)"    # zsh
```

`completions [bash|zsh]` prints the script (default `bash`). Completions are generated natively by Bashly 2
(`completions: full` in `./bashly-settings.yml`); model, preset and service names complete dynamically.

## 📖 Command reference

### `setup`

Run with `sudo`. `setup` alone runs `setup all`. Details: [Installation](installation.md#-run-the-setup).

| Subcommand  | Purpose                                              | Flags (env var)                                                                                        |
| ----------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `all`       | Interactive full workstation setup, every step below | `-n` `--server-name`, `-u` `--allowed-user`, `-p` `--ssh-port`, `-t` `--timezone`, `-d` `--lvm-device` |
| `init`      | Extend storage and set timezone                      | `-t` `--timezone` (`panther_timezone`), `-d` `--lvm-device` (`panther_lvm_device`)                     |
| `packages`  | Install essential packages                           | —                                                                                                      |
| `brew`      | Install Homebrew, `llmfit`, `hf`, `yq`               | `-u` `--allowed-user` (`panther_allowed_user`)                                                         |
| `docker`    | Install Docker, add user to the `docker` group       | `-u` `--allowed-user`                                                                                  |
| `tailscale` | Install Tailscale                                    | —                                                                                                      |
| `ssh`       | Harden SSH                                           | `-u` `--allowed-user`, `-p` `--ssh-port` (`panther_ssh_port`)                                          |
| `ufw`       | Configure the firewall                               | `-p` `--ssh-port`                                                                                      |
| `fail2ban`  | Install and configure fail2ban                       | `-p` `--ssh-port`                                                                                      |
| `amdgpu`    | Install AMD GPU drivers and ROCm                     | —                                                                                                      |
| `grub`      | Update GRUB kernel parameters                        | —                                                                                                      |
| `git`       | Configure Git defaults                               | `-n` `--server-name` (`panther_server_name`), `-u` `--allowed-user`                                    |
| `shell`     | Install Starship and configure the shell             | `-u` `--allowed-user`                                                                                  |
| `env`       | Create `.env`, sync GPU group IDs and `BIND_ADDR`    | `-u` `--allowed-user`                                                                                  |

Defaults: SSH port `2222`, timezone `Europe/Prague`, LVM device `/dev/ubuntu-vg/ubuntu-lv`, current user and host
name.

### `models`

| Command                       | Purpose                                                       | Flags                                                                                                 |
| ----------------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `models llm list`             | List supported LLMs                                           | —                                                                                                     |
| `models llm download <model>` | Download into the shared Hugging Face cache (uses `HF_TOKEN`) | `-f` `--force`                                                                                        |
| `models llm remove <model>`   | Remove files no other model uses                              | —                                                                                                     |
| `models llm load <preset>`    | Load a preset into `llama-server`                             | —                                                                                                     |
| `models llm unload <preset>`  | Unload a preset                                               | —                                                                                                     |
| `models llm bench <preset>`   | Measure decode/prefill, append to `models/bench.log`          | `-n` `--tokens` (256), `-r` `--runs` (3), `-w` `--warmups` (8), `-L` `--loads` (1), `-l` `--log-path` |
| `models t2i list`             | List supported text-to-image models                           | —                                                                                                     |
| `models t2i download <model>` | Download components (uses `HF_TOKEN`)                         | `-f` `--force`                                                                                        |
| `models t2i remove <model>`   | Remove components no other model uses                         | —                                                                                                     |
| `models t2i load <model>`     | Serve a model in `sd-server`, replacing the current one       | `-e` `--exclusive`                                                                                    |
| `models t2i unload`           | Stop `sd-server`, return dedicated GPUs to the LLMs           | —                                                                                                     |
| `models prune`                | Delete cached files no catalog references                     | —                                                                                                     |

`<model>` is a name from `models/*.config.json`; `<preset>` is a section of `llama-cpp/preset.ini`. Details:
[Models](models.md), [LLM serving](llm.md), [Image generation](image-generation.md).

## ✍️ Maintainer workflow

After changing the authored CLI sources, regenerate the CLI (the pre-commit hook also does this):

```bash
pnpm run build:cli
```

### Edit the right files

| Path                      | Responsibility                                                                  |
| ------------------------- | ------------------------------------------------------------------------------- |
| `./cli/bashly.yml`        | Command tree, flags, args, examples, and env vars                               |
| `./cli/commands/**/*.sh`  | Command entrypoints (`models llm bench` → `./cli/commands/models/llm/bench.sh`) |
| `./cli/lib/*.sh`          | Shared helper logic                                                             |
| `./cli/lib/validations/*` | Custom validations                                                              |
| `./cli/initialize.sh`     | Pre-parse normalization and bootstrapping                                       |
| `./bashly-settings.yml`   | Bashly settings (`completions: full`)                                           |

### Editing rules

- `./cli/bashly.yml` is the CLI schema source of truth.
- Prefer `bashly generate` **without** `--force`; `--force` can recreate placeholder command files and overwrite
  authored command bodies.
- Update this page's [command reference](#-command-reference) and, for new top-level groups, the
  [command groups](#-command-groups) table.

### Implementation notes

- Routine status output uses `panther_log_info`, `panther_log_success`, `panther_log_warn` and `panther_log_error`.
- Env support is declared per command in `./cli/bashly.yml`.
- The CLI does not globally load `.env`; commands that need it call `panther_load_dotenv` (`models llm|t2i download`,
  `models t2i load --exclusive`, `models t2i unload`), while Docker Compose still reads `.env`.
- Per-argument completions live on the arg in `./cli/bashly.yml` as `completions: { static | dynamic | options }`.

### Validate after changes

```bash
bash -n ./bin/panther-minor
./bin/panther-minor --help
```

The `cli-command` agent skill (`.agents/skills/cli-command/SKILL.md`) encodes this workflow step by step.

## ❓ FAQ

### Why must I never edit `bin/panther-minor`?

It is regenerated from `cli/` on every `pnpm run build:cli` (and by the pre-commit hook), so hand edits are lost.

### My new command file came out as a placeholder. What happened?

`bashly generate --force` recreates command files from templates. Restore the body from Git and regenerate without
`--force`.

### Why doesn't a command see my `.env` value?

Only commands that call `panther_load_dotenv` read `.env`: `models llm|t2i download`, `models t2i load --exclusive`
and `models t2i unload`. Every other command sees only your shell environment, so export the variable or pass it
inline (`VAR=value ./bin/panther-minor …`).

### Completions don't show new commands. Why?

Your shell still holds the old script. Rebuild, then re-run `source .bashrc` (or the `eval` line for zsh).
